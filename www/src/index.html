what it does

A complete client, not a demo.

Everything below ships today in the free, AGPL-3.0 build. Nothing on this list is held back or headed for a paid tier.

Unified inbox
Every configured account in one view, plus a per-account view. Conversation threading, unread counts and the full folder tree per account.
Background sync
IMAP IDLE with polling fallback, one connection per account. New mail arrives without a refresh; Gmail and Zoho over OAuth2, everything else over passwords.
Search, streamed
Instant local full-text search, plus on-demand deep IMAP server search streamed back over SSE as results arrive.
Compose
Reply, reply-all and forward over SMTP — plain text, rich text or Markdown — with local draft autosave, undo-send and scheduled send.
Filters & rules
A rule engine (conditions → move, label, forward, mark read, star, delete, notify) that runs on incoming mail, on your server.
Keyboard-first
A full shortcut set for navigating and triaging without the mouse — j k e s R / and ? for the rest.
PWA & push
Installs as an app with an offline fallback to your last-synced inbox. Web Push from your own server (end-to-end encrypted payloads), or a POST to any ntfy topic.
AI, bring-your-own-key
Optional AI compose/reply and translate (OpenRouter, Google Translate). Off by default, keys stay in your database.
Backup = cp
All state lives in one SQLite file — accounts, credentials, cache, sessions, filters, tokens. Back up the directory and you've backed up everything.

how you get it

One command to boot. Zero config to run.

  1. 01

    Start it. The compose file below is the whole deployment. One container, one volume, one port.

  2. 02

    Open it. The first visit walks you through creating your admin account. There is nothing else to bootstrap.

  3. 03

    Point it at your mail. Add accounts under Settings → Accounts — OAuth2 for Gmail and Zoho, app passwords everywhere else. Changes take effect without a restart.

why self-hosted

Nobody between you and your mail.

No account to create

mimux asks nobody's permission to read your mail. It talks IMAP and SMTP directly to providers you already use, with credentials that live in your SQLite file.

No telemetry

The application phones home to no one: no CDNs, no analytics, no tracking — everything is bundled in the binary. Remote images in emails stay blocked until you say otherwise.

Open, all the way down

AGPL-3.0. One Go binary serving htmx and Alpine.js over SQLite — small enough to read end to end, boring enough to run for years.

Yours on bad days

If the author vanishes, nothing changes for you — the binary you run keeps working, the source is yours, and your mail was never locked anywhere to begin with.

what's coming

An inbox your agents can act on.

roadmap — not released yet

Agent frameworks can search the web and run code, but they can't read your mail unless you hand your inbox to a SaaS intermediary. The mimux pro layer closes that gap on your own hardware:

REST API

Messages, folders, search, send, drafts and filters over plain HTTP, with an OpenAPI spec served from the binary.

MCP server

Your inbox as a first-class tool for agents — read, search, triage and draft, from any MCP-capable client.

Webhooks

New mail and rule matches pushed to whatever automation you run — n8n, Home Assistant, your own scripts.

The line doesn't move: a human driving mimux is free; a machine driving mimux is paid. The paid layer is automation only, published in advance so its arrival is a plan being executed, not a surprise.
